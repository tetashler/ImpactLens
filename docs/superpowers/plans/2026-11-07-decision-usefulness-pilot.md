# Decision usefulness pilot implementation plan

**Goal:** Make a runnable local human-review pilot comparing a frozen source-backed brief with exactly that brief plus recorded ImpactLens synthetic discussion. No human findings, interviews or validated demand are invented.

**Architecture:** Browser-safe study/packet/response contracts and deterministic counterbalanced assignment; six source-backed hypothetical Singapore cases; strict import of actual V2 public report discussion excerpts against the exact brief-bearing generation question; CLI preparation/packet export/coding/analysis; dedicated `/evaluation` local reviewer interface using the existing chart-room palette. No new AI calls, remote submission, automatic simulation recovery, dependencies, storage migrations or mobile work. User has no identified reviewers; recruitment stays unassigned.

## Method

Recruit 3–5 people who prepare service-location or consultation briefs; conduct a short workflow interview before the evaluation. Each independently reviews all six cases, seeing one condition per case, three source-only and three augmented. Seeded case order and alternating condition assignment balance each case across reviewers to within one. No same-case crossover; six related cases still permit learning and tiny samples are descriptive only. Packets contain only their assigned version, no answer keys, other participants or condition key. They disclose that any synthetic dialogue is fictional; complete condition blinding is impossible.

All six augmented cases must have actual imported output before real packets can be built. No handcrafted dialogue can masquerade as AI output. For each case, `generationQuestion` includes its frozen brief; attach only a strict V2 report whose question equals it exactly and which contains retained discussion-event evidence. This verifies prompt-text identity, not that the model used the evidence correctly or that its discussion resembles residents. Record run ID/snapshot/time and source question; bounded excerpts can omit issues and their absence must not be interpreted as absence from a full run.

Measure listed concerns, stakeholder coverage, claims requiring checking, research questions and active review time. Independent human coding judges usefulness/actionability/support; do not automatically score semantic quality. Suggested stakeholder keys are provisional expert-review aids, not population ground truth. Cases include three explicit insufficient-evidence targets. Keep missing coding null; never count absent ratings as zero. Summary reports per-case/condition counts, means and raw data without p-values, confidence intervals or population-benefit claims. Initial pilot tests feasibility and possible usefulness, not Singapore resident fidelity or market demand.

## Exact shared interfaces

Module `lib/decision-pilot/core.ts` exports types and parsers below plus `pilotHash(value):Promise<string>` (SHA256 canonical JSON), `makePilotStudy(cases, reviewerIds, seed):Promise<PilotStudy>`, `makeReviewerPacket(study,reviewerId):Promise<ReviewerPacket>`, `parseReviewerPacket(value)`, `parsePilotReviews(value)`, `analysePilot(study,reviews,codings)`.

`PilotSource={id,title,url,publisher,accessedAt,summary}`. Summary is a short authored paraphrase, not a verbatim passage or site-specific finding.

`PilotCase={id,title,question,decisionQuestion:string,brief:string,sourceIds:string[],sources:PilotSource[],generationQuestion:string,reference:{expectedDecision:'insufficient-evidence'|'supported',stakeholders:string[],limitations:string[]},supplement:null|{runId,snapshotKey,generatedAt,items:{id,text,actorLabel}[]}}`.

`PilotStudy={version:1,kind:'decision-pilot-study',id:string,seed:string,reviewerIds:string[],cases:PilotCase[],assignments:{reviewerId,caseId,condition:'brief'|'discussion',order:number}[]}`. Exactly six unique cases and 3–5 unique pseudonymous reviewer IDs; all six supplements required. `id` is a hash of the remaining content. No human evidence or output is bundled by default.

`ReviewerPacket={version:1,kind:'decision-pilot-packet',studyId,reviewerId,id,items:{id:string,caseId,order,question,decisionQuestion,brief,sources:PilotSource[],discussion:{id,text,actorLabel}[]}[]}`. Each item contains its assigned content only; no reference key, condition label or unassigned supplement. `id` binds remaining packet content; helpers must verify it on import. Public source URLs HTTPS only, no credentials/IP/localhost. Limit each file 300KB, six cases, 12 discussion excerpts/case, 900 chars/excerpt, 12 sources/case; brief/generationQuestion max1,600/2,000 chars, reviewer notes/item text max1,200, max12 response items/category. References in responses may use only actual packet source or discussion IDs.

`PilotReview={id:string,studyId,packetId,reviewerId,caseId,itemId,decision:'insufficient-evidence'|'supported',concerns:{id,text,referenceIds:string[]}[],stakeholders:string[],claims:{id,text,referenceIds:string[]}[],questions:{id,text}[],activeMilliseconds:number,elapsedMilliseconds:number,submittedAt:string,independent:true}`. Elapsed spans first Start through submission including pauses/source checks/breaks; active excludes hidden and paused time. Both bounded to two hours, active <= elapsed. Neither is silently labeled total productive review time.

`PilotReviews={version:1,kind:'decision-pilot-reviews',studyId,packetId,reviewerId,reviews:PilotReview[]}`. Review ID is `reviewerId+':'+caseId`; list IDs simple category prefix + index. Metadata must bind exact packet item, assignment and study on analysis. Duplicates/replaced content/condition contamination must be rejected, not double-counted. Incomplete reviewer files allowed and explicitly missing. Inputs contain pseudonyms, not contact details.

`PilotCoding={reviewId,reviewHash,coderId,usefulConcernIds:string[],missedStakeholders:string[],unsupportedClaimIds:string[],additionalUnsupportedClaims:string[],actionableQuestionIds:string[],decisionCorrect:boolean,notes:string}`. Human judgment, not automatic ground truth. `analysePilot` returns an object with `status:'awaiting-reviews'|'needs-coding'|'descriptive-results'`, `counts`, `byCondition` and `rows`. Only one final human coding per review is accepted; duplicate/conflicting rows reject. Protocol requires independent coding first then a separate final adjudicated file. Code must validate IDs exist in that review, unknown reviewers/cases and elapsed bounds. reviewHash binds the full response; stale coding rejects replaced text, decision or timing. additionalUnsupportedClaims contains human-audited unsupported packet assertions missed by the reviewer; detected and additionally found claims require interpretation, not an automatic error verdict. Conditions derived from assignments, never reviewer-supplied. Empty inputs must not claim benefit.

Core should expose `parsePilotCase` (allows unfinished supplement:null), `parsePilotStudy`, `parsePilotCoding` and async packet verification helper `verifyReviewerPacket(value)` for callers. `parseReviewerPacket` is structural and `verifyReviewerPacket` validates its hash. `parsePilotReviews` accepts incomplete exports; analysis revalidates full study and packet correspondence. `analysePilot` is asynchronous to verify hashes using Web Crypto. Metrics fields per row: usefulConcerns, missedStakeholders, unsupportedClaims, actionableQuestions, activeMinutes, elapsedMinutes, decisionCorrect; uncoded quality metrics null. Include per-case/condition observation counts, missing observations and no causal conclusion.

## Tasks and file ownership

1. Core/analysis + focused tests: `lib/decision-pilot/core.ts`, `lib/contracts/tests/decision-pilot-core.test.ts`. Fail first for missing module; check assignments, withheld keys, semantic-no-score nulls, unknown/missing/duplicate coding, reference binding, arithmetic, no reviewers => no benefit. Do not import Node modules into browser code.
2. Reviewer UI + focused tests: `components/decision-pilot.tsx`, scoped CSS, `lib/decision-pilot/reviewer.ts` pure timer/controller if useful, `app/evaluation/page.tsx`. Accept per-reviewer packet upload only; verify hash, explicit consent and independence; show one item at a time, Start/Pause/Resume timer with visibility auto-pause, manual text response capture, complete/export pseudonymous JSON. Timer excludes paused/hidden intervals, active max2h/case. In-memory only; no autosave or network upload. Clear prior responses/timers when another packet is imported. Import files <=300KB, safe escaped text/URLs. Export helper named `PilotPacketView` for rendering if useful. Existing chart-room style, accessible labels. No creator answer keys or aggregate results in reviewer mode.
3. Root authors six cases, attach/report intake, CLI, recruitment/interview/analysis protocol and research rationale. New `lib/decision-pilot/cases.ts` exports `pilotCases`; `lib/decision-pilot/authoring.ts` exports `attachPilotDiscussion(caseValue,report):PilotCase` strict V2 input identity/excerpts. CLI `scripts/decision-pilot.ts`: `questions --out`, `attach --case --report --out`, `build --cases --reviewers R01,R02,R03 --seed --out`, `analyse --study --reviews <directory> --coding <file optional> --out`. Exclusive writes, preserve inputs; generated files under caller-selected output, no private state reads by default. `questions` produces author case bundle JSON and exact generation prompts, no ready study until all six outputs attached. Add `pilot:decision` package script. Author bundles are arrays of six cases; attach command takes `--cases` file or seed defaults and exports updated full array.
4. Independent method/privacy review, focused regression tests, TypeScript, documented Webpack build and browser packet/timer/export tests with a clearly marked test-only fixture. No genuine human data or evaluation outcomes produced by agents. No contacts or outreach sent; user must recruit/interview real participants. No commit/push until requested.
